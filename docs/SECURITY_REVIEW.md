# FinderRight 1.2.0 安全检查

检查日期：2026-09-28。范围为本仓库的源代码、构建配置、发布包和本机运行行为。

结论：在本次检查范围内，未发现有意植入的后门、恶意程序、数据回传、远程下载执行、隐藏账号或未经用户选择的自启动逻辑。检查发现的本地通信和权限问题已在 1.2.0 中修订。这个结论不等于绝对无漏洞，也不等于 Apple 公证或第三方安全认证。

## 检查方法

- 阅读主应用、Finder 扩展、共享库、设置界面和构建脚本的执行入口。
- 检查联网、进程创建、文件写入和删除、URL scheme、系统服务、自启动、辅助功能与签名权限。
- 检查 Git 跟踪文件类型、Swift Package 依赖、Xcode 构建阶段和 CI 工作流。
- 检查 Mach-O 动态依赖、双架构、签名、权限和安装后进程。
- 在隔离的临时文件目录中进行正常请求、伪造调用、取消系统服务及异常文件测试。

未进行整个操作系统的恶意软件扫描，也没有上传用户文件或安装包到第三方查毒服务。没有使用 VirusTotal 等服务的“零检出”来替代源码分析。

## 本次修订

### 认证本地请求来源

旧版只检查 JSON 文件和 UUID，其他本机程序可以伪造相同的调用方式。新版读取当前 Apple Event 的内核 audit token，经 Security.framework 验证调用方进程，要求其标识和代码哈希匹配当前安装包中的 FinderRightSync。应用不信任请求文件或 URL 参数提供的 PID。

扩展同时在该事件 URL 中携带 JSON 的 SHA-256 摘要。主应用验证内容一致，防止把真实扩展发来的通知与被替换的文件内容拼接起来。请求采用私有目录、0600 文件、UUID 文件名，拒绝符号链接、硬链接、非普通文件、错误所有者、共享权限和超大文件，消费后移除请求。

### 收紧动作和权限

操作名称及参数使用白名单。终端和编辑器限制为产品支持的应用，不接受任意程序标识或 CLI 路径。请求总量、文件数量、路径、图片尺寸及模板内容有上限。终端动作只接受文件夹。

Finder 扩展移除了进程执行、Apple Events、下载目录、外部卷及云盘目录的广泛例外，只保留沙箱、用户选择文件访问及 FinderRight 自身配置和 IPC 目录的访问。

### 系统服务需要确认

macOS Services 可以被其他程序调用，无法等同于认证过的 Finder 扩展。所有 Services 操作均显示动作、文件数量和可滚动的完整路径列表，确认后才执行。默认按钮为取消，避免意外按 Return 执行操作。普通 FinderRight 原生右键菜单不增加此确认。

### 构建来源可核对

发布模式使用 `git archive HEAD` 的提交快照构建，排除未跟踪文件与本地工程副本。CI 的第三方 actions 固定到提交哈希。发布附件提供 BUILD-INFO.json 和 SHA-256 校验值，关联源码提交、架构与签名状态。

## 验证证据

- 26 项自动化测试覆盖文件保全、重命名、压缩包越界、图片、PDF、请求篡改、重放、链接、FIFO、大小和权限，以及动作白名单。
- 在安装版上，通过真实 Finder 扩展创建副本成功，内容与源文件一致，证明来源验证仍允许正常操作。
- 独立 Swift 进程使用有效 UUID、合法 JSON 和正确摘要模拟调用，应用明确拒绝非 FinderRight 扩展来源，没有生成副本。
- 独立进程程序化调用 macOS Services，应用显示确认提示。选择取消后没有压缩产物。
- 发行前对最终安装包重新验证签名、架构及文件校验和。

## 边界与限制

- macOS 26.6.2 的 Apple Silicon 设备完成了本机验证。Intel 和最低 macOS 13 的运行仍未进行实机覆盖，当前完成的是对应架构与部署目标编译。
- 文件、配置和剪切队列位于当前用户账户内。应用不承诺隔离已被控制的用户账户、管理员或 root，也不能保护系统框架自身的未知漏洞。
- 处理不可信压缩包、图片和 PDF 时，仍应保持 macOS 更新。超大数据和异常文件可能导致操作失败。
- 未公证版本首次打开可能被 Gatekeeper 阻止，应按系统的单应用提示处理，不应关闭全局安全保护。
- 这次审查支持发布开源桌面工具版本，不构成所有环境、所有功能均已验收的声明。
