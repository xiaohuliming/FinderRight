## Finder 扩展启用问题复验

2026-09-28 晚间，在 macOS 26.6.2 复现了“管理扩展能打开系统设置，但列表里没有 FinderRight”的问题。此前运行的应用位于临时 DerivedData 目录；扩展可以出现在 pluginkit 注册记录中，却不显示在系统设置的开关列表。

将完全相同且签名校验通过的 Debug 应用复制到 `/Applications/FinderRight.app`，退出临时副本并从新位置启动后，系统设置立即出现 FinderRight 开关。确认该安装条件后，又换成通用架构 Release 构建并再次验证。

- [x] 系统设置的实际路径为“通用 → 登录项与扩展 → 文件提供程序”，其中 FinderRight 开关已打开。
- [x] 应用中的 Finder 扩展状态显示已启用，与系统开关一致。
- [x] 正式安装路径的 FinderRightSync 进程成功运行，临时构建的重复注册已清理。
- [x] 普通本地测试目录的原生右键菜单出现“复制信息”“文件整理”“开发工具”。
- [x] 通过原生菜单执行“创建副本”，Debug 安装版和最终 Release 安装版都成功生成副本，内容与原文件逐字节一致。
- [x] 最终安装包通过通用架构、严格签名和 SHA-256 检查，安装版不含 Debug 的 get-task-allow entitlement。
- [x] 未开启完全磁盘访问或辅助功能权限，未修改其他应用的扩展开关。

此前文档中“普通目录 FinderSync 尚未完成激活和基本调用验收”的限制已由本次证据补足。此结果不表示所有文件功能、外接盘、第三方云盘或最低 macOS 版本都已完成验收。

主应用现在增加了安装位置提示。未从标准 Applications 路径运行时，提醒先移动应用后重新打开；在 macOS 26 上明确提示到“文件提供程序”查找开关。文件操作、IPC 和 FinderSync 业务代码没有改动。
